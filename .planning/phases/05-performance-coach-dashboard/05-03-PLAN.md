<task type="auto">
  <name>Task 1: Create CoachService with roster, PMC summary, alerts, and relationship methods</name>
  <files>backend/app/services/coach_service.py</files>
  <action>
Create `backend/app/services/coach_service.py` with a `CoachService` class following the established pattern (see PMCService, PerformanceService).

Include these methods:

**`async def get_coach_id(self, user_id: str) -> str`**
- Query `coaches` table for coach record with matching user_id
- Return the coach UUID
- Raise ValueError if no coach record found

**`async def get_athlete_ids(self, coach_id: str) -> list[str]`**
- Query `coach_athletes` where coach_id matches AND ended_at IS NULL
- Return list of athlete_id strings

**`async def get_roster(self, coach_id: str) -> list[dict]`**
- Query `coach_athletes` with joined athlete data:
  `.select("athlete_id, relationship_type, access_level, started_at, athletes(id, first_name, last_name, email, is_active)")`
  `.eq("coach_id", coach_id).is_("ended_at", "null")`
- Return the data array

**`async def get_athletes_pmc_summary(self, coach_id: str) -> list[dict]`**
- Get athlete_ids via get_athlete_ids
- For each athlete, call `PMCService().calculate_pmc_for_athlete(athlete_id, days=14)`
- Build summary: athlete_id, current_ctl (last value or 0), current_atl, current_tsb, last_load_date
- Use batch approach where practical but PMC calculation is per-athlete (requires sequential calls due to the exponential decay math)
- Round values to 1 decimal place

**`async def generate_alerts(self, coach_id: str) -> list[dict]`**
Compute alerts on read (do NOT store in notifications table). Query data for all coached athletes and check for:

1. **missed_checkin**: Query `wellbeing_assessments` for each athlete, check if latest assessment date is 2+ days ago. Severity: "medium".
2. **low_readiness**: Query `wellbeing_assessments` for last 2 days, if average score < 4, alert. Severity: "high". Use the same readiness calculation as wellbeing.py `_calculate_readiness`.
3. **fatigue_spike**: Use PMC data -- if current TSB < -20 OR ATL/CTL ratio > 1.5, alert. Severity: "high".
4. **overtraining_risk**: If TSB < -30 for current snapshot. Severity: "high".

Return list of alert dicts: `{type, severity, athlete_id, athlete_name, message, date}`

Batch the wellbeing queries: use `.in_("athlete_id", athlete_ids)` to avoid N+1 queries (per research pitfall #3).

**`async def add_athlete(self, coach_id: str, athlete_id: str, relationship_type: str = "primary") -> dict`**
- Insert into coach_athletes: coach_id, athlete_id, relationship_type, access_level="full", started_at=today
- Return the inserted row

**`async def remove_athlete(self, coach_id: str, athlete_id: str) -> dict`**
- Soft-remove: UPDATE coach_athletes SET ended_at = today WHERE coach_id AND athlete_id AND ended_at IS NULL
- Return the updated row

Import `get_supabase` from `app.db.session` and `PMCService` from `app.services.pmc_service`.

Use Google-style docstrings matching the existing codebase convention.

  <name>Task 2: Create coach API endpoints and register router</name>
  <files>backend/app/api/endpoints/coach.py, backend/app/api/router.py</files>
  <action>
Create `backend/app/api/endpoints/coach.py` following the same pattern as training.py and wellbeing.py.

**Endpoints:**

1. **GET /roster** - `get_coach_roster(user=Depends(get_current_user))`
   - Check role via _get_user_role (copy the helper from wellbeing.py -- same pattern used throughout)
   - If not coach, return 403
   - Get coach_id via CoachService.get_coach_id(user.id)
   - Return CoachService.get_roster(coach_id)

2. **GET /athletes/pmc-summary** - `get_athletes_pmc_summary(user=Depends(get_current_user))`
   - Coach role check
   - Return CoachService.get_athletes_pmc_summary(coach_id)

3. **GET /alerts** - `get_coach_alerts(user=Depends(get_current_user))`
   - Coach role check
   - Return CoachService.generate_alerts(coach_id)

4. **POST /athletes/{athlete_id}** - `add_athlete_to_roster(athlete_id: str, relationship_type: str = Query("primary"), user=Depends(get_current_user))`
   - Coach role check
   - Verify athlete exists in athletes table
   - Return CoachService.add_athlete(coach_id, athlete_id, relationship_type)
   - Return 201 on success

5. **DELETE /athletes/{athlete_id}** - `remove_athlete_from_roster(athlete_id: str, user=Depends(get_current_user))`
   - Coach role check
   - Return CoachService.remove_athlete(coach_id, athlete_id)

All endpoints should be wrapped in try/except with proper HTTP error responses following the existing pattern:
```python
except HTTPException:

except RuntimeError as e:
    raise HTTPException(status_code=503, detail=str(e))
except Exception as e:
    raise HTTPException(status_code=500, detail=f"Failed to ...: {str(e)}")
```
