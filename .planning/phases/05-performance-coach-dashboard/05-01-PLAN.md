  <name>Task 1: Add sRPE training load upsert to workout PATCH endpoint</name>
  <files>backend/app/api/endpoints/training.py</files>
  <action>
In the existing PATCH /workouts/{workout_id} endpoint in training.py, add logic AFTER the successful update to calculate and upsert training load when a workout is marked complete with RPE.

Add a helper function `_upsert_training_load(workout: dict)` at the module level:
- Takes the updated workout dict (must have athlete_id, date, rpe, and duration)
- Calculates sRPE: `training_load = rpe * duration` (duration is the `duration` column, which is integer minutes in the production schema)
- Queries training_loads table for existing row matching athlete_id + date
- If exists: update training_load to existing + new sRPE (supports multiple sessions per day)
- If not exists: insert new row with athlete_id, date, training_load, rpe fields

Call this function in the PATCH handler AFTER the supabase update succeeds, but only when:
1. The update includes `is_completed = True` (or the workout was already completed)
2. The workout has both `rpe` and `duration` values

After the PATCH update, re-fetch the full workout row to get athlete_id, date, rpe, duration. Then call `_upsert_training_load()`.

Important notes:
- The production workouts table column is `duration` (integer, minutes), NOT `duration_minutes`
- The production workouts table uses `type` column, NOT `workout_type` (but the API may have renamed this -- check the existing PATCH logic)
- Use `get_supabase()` from `app.db.session` (already imported in the file)
- Wrap the training load upsert in try/except so a failure here does not break the workout update response -- log the error but still return success
- Do NOT change the existing PATCH response or allowed_fields whitelist
