Database table (production_schema.sql):
```sql
CREATE TABLE public.wellbeing_assessments (
  id uuid NOT NULL DEFAULT uuid_generate_v4(),
  user_id uuid NOT NULL,
  date date NOT NULL,
  sleep_quality integer,
  stress_level integer,
  nutrition_quality integer,
  physical_readiness integer,
  mental_clarity integer,
  notes text,
  created_at timestamp with time zone DEFAULT now(),
  updated_at timestamp with time zone DEFAULT now(),
  CONSTRAINT wellbeing_assessments_pkey PRIMARY KEY (id),
  CONSTRAINT wellbeing_assessments_user_id_fkey FOREIGN KEY (user_id) REFERENCES auth.users(id)
);
```

Key decisions from STATE.md:
- Return raw dicts from Supabase (no response_model) to avoid Pydantic validation mismatches
- Auth guard as Depends(get_current_user) per endpoint
- Auto-set user_id on create (never trust client input for ownership)
- Coach role check via _get_user_role helper (app_metadata first, user_metadata fallback)
- Backend uses service role key (bypasses RLS)

       Endpoints:
       a) POST /checkin — Submit daily check-in
          - Accepts CheckInCreate body
          - Sets user_id from authenticated user (NEVER from client)
          - Sets date to today (server-side, ISO format YYYY-MM-DD)
          - Calculates readiness_score: weighted average of metrics = round((sleep_quality + (10 - stress_level) + nutrition_quality + physical_readiness + mental_clarity) / 5)
          - Determines recovery_status from readiness_score: >=8 "green", >=5 "yellow", <5 "red"
          - Upserts to wellbeing_assessments (unique on user_id + date)
          - NOTE: The production table does NOT have readiness_score or recovery_status columns. Store only the columns that exist: sleep_quality, stress_level, nutrition_quality, physical_readiness, mental_clarity, notes. Calculate readiness_score and recovery_status on read, not on write.
          - When flag_concern is True, prepend "[CONCERN] " to the notes field before saving (e.g., notes becomes "[CONCERN] Left knee pain after sprints"). If flag_concern is True and notes is empty/None, set notes to "[CONCERN]". This encodes the concern flag into the existing notes column without requiring a schema migration.
          - Returns the saved row plus calculated readiness_score and recovery_status

       b) GET /checkin/today — Get today's check-in for authenticated user
          - Query wellbeing_assessments where user_id = auth user and date = today
          - Return data with calculated readiness_score and recovery_status, or 204 No Content if none
          - Include has_concern: bool derived from whether notes starts with "[CONCERN]" (for frontend pre-fill of checkbox)

       c) GET /history — Get wellbeing history for authenticated user
          - Query params: days (int, default 30)
          - Query wellbeing_assessments where user_id = auth user, date >= today - days
          - Order by date ascending
          - Return list of assessments with calculated readiness for each

       d) GET /coach/readiness — Coach-only: get readiness status for all athletes
          - Check user role is "coach" (use _get_user_role pattern from training.py)
          - Query all athletes where coach_id matches (via athletes table)
          - For each athlete, get their latest wellbeing_assessment
          - Return list of {athlete_id, athlete_name, date, readiness_score, recovery_status, has_injury_flag} where has_injury_flag = notes starts with "[CONCERN]" (NOT just any non-empty notes — only explicit concern flags count)
          - If athlete has no check-in today, recovery_status = "gray" (no data)

       Helper function for readiness calculation:
       ```python
       def _calculate_readiness(row: dict) -> dict:
           score = round((row["sleep_quality"] + (10 - row["stress_level"]) + row["nutrition_quality"] + row["physical_readiness"] + row["mental_clarity"]) / 5)
           status = "green" if score >= 8 else "yellow" if score >= 5 else "red"
           has_concern = bool(row.get("notes", "") and row["notes"].startswith("[CONCERN]"))
           return {**row, "readiness_score": score, "recovery_status": status, "has_concern": has_concern}
       ```
