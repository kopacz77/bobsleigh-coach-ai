  **Create `backend/sql/rls_policies_migration.sql`:**

  This SQL file replaces the permissive `USING (true)` policies from the fresh_clean_schema with proper auth-based policies. It should be run in the Supabase SQL editor AFTER the auth_roles_migration.sql from Plan 02-03.

  **Important context:** The backend uses `get_supabase()` with the SERVICE_ROLE_KEY, which BYPASSES RLS. This is intentional -- the backend handles its own authorization logic in Python. The RLS policies protect against direct Supabase client access from the frontend (which uses the anon key and respects RLS).

  The SQL should:

  1. **Drop existing permissive policies:**
     ```sql
     -- Drop overly permissive policies from fresh_clean_schema
     DROP POLICY IF EXISTS "Athletes manage own data" ON public.athletes;
     DROP POLICY IF EXISTS "Athletes manage workouts" ON public.workouts;
     DROP POLICY IF EXISTS "Athletes manage workout_exercises" ON public.workout_exercises;
     DROP POLICY IF EXISTS "Athletes manage performance" ON public.performance_metrics;
     DROP POLICY IF EXISTS "Athletes manage loads" ON public.training_loads;
     DROP POLICY IF EXISTS "Athletes manage wellbeing" ON public.wellbeing_assessments;
     DROP POLICY IF EXISTS "Athletes manage recommendations" ON public.training_recommendations;
     ```

  2. **Athletes table policies:**
     ```sql
     -- Athletes can read their own profile
     CREATE POLICY "athletes_select_own" ON public.athletes
       FOR SELECT USING (user_id = auth.uid());

     -- Athletes can update their own profile
     CREATE POLICY "athletes_update_own" ON public.athletes
       FOR UPDATE USING (user_id = auth.uid());

     -- Coaches can read profiles of their assigned athletes
     CREATE POLICY "coaches_select_athletes" ON public.athletes
       FOR SELECT USING (
         EXISTS (
           SELECT 1 FROM public.coaches c
           JOIN public.coach_athletes ca ON ca.coach_id = c.id
           WHERE c.user_id = auth.uid()
           AND ca.athlete_id = athletes.id
         )
       );

     -- Service role can do everything (for backend operations)
     -- Note: Service role key automatically bypasses RLS, so no explicit policy needed
     ```

  3. **Workouts table policies:**
     ```sql
     -- Athletes can CRUD their own workouts
     CREATE POLICY "athletes_select_own_workouts" ON public.workouts
       FOR SELECT USING (
         athlete_id IN (SELECT id FROM public.athletes WHERE user_id = auth.uid())
       );

     CREATE POLICY "athletes_insert_own_workouts" ON public.workouts
       FOR INSERT WITH CHECK (
         athlete_id IN (SELECT id FROM public.athletes WHERE user_id = auth.uid())
       );

     CREATE POLICY "athletes_update_own_workouts" ON public.workouts
       FOR UPDATE USING (
         athlete_id IN (SELECT id FROM public.athletes WHERE user_id = auth.uid())
       );

     -- Coaches can read workouts of their assigned athletes
     CREATE POLICY "coaches_select_workouts" ON public.workouts
       FOR SELECT USING (
         EXISTS (
           SELECT 1 FROM public.coaches c
           JOIN public.coach_athletes ca ON ca.coach_id = c.id
           WHERE c.user_id = auth.uid()
           AND ca.athlete_id = workouts.athlete_id
         )
       );
     ```

  4. **Workout exercises table policies:**
     ```sql
     -- Athletes can CRUD exercises in their own workouts
     CREATE POLICY "athletes_select_own_workout_exercises" ON public.workout_exercises
       FOR SELECT USING (
         workout_id IN (
           SELECT w.id FROM public.workouts w
           JOIN public.athletes a ON a.id = w.athlete_id
           WHERE a.user_id = auth.uid()
         )
       );

     CREATE POLICY "athletes_insert_own_workout_exercises" ON public.workout_exercises
       FOR INSERT WITH CHECK (
         workout_id IN (
           SELECT w.id FROM public.workouts w
           JOIN public.athletes a ON a.id = w.athlete_id
           WHERE a.user_id = auth.uid()
         )
       );

     -- Coaches can read workout exercises of their assigned athletes
     CREATE POLICY "coaches_select_workout_exercises" ON public.workout_exercises
       FOR SELECT USING (
         workout_id IN (
           SELECT w.id FROM public.workouts w
           JOIN public.coaches c ON c.user_id = auth.uid()
           JOIN public.coach_athletes ca ON ca.coach_id = c.id AND ca.athlete_id = w.athlete_id
         )
       );
     ```

  5. **Performance metrics policies:**
     ```sql
     -- Athletes read own, coaches read assigned athletes'
     CREATE POLICY "athletes_select_own_performance" ON public.performance_metrics
       FOR SELECT USING (
         athlete_id IN (SELECT id FROM public.athletes WHERE user_id = auth.uid())
       );

     CREATE POLICY "coaches_select_performance" ON public.performance_metrics
       FOR SELECT USING (
         EXISTS (
           SELECT 1 FROM public.coaches c
           JOIN public.coach_athletes ca ON ca.coach_id = c.id
           WHERE c.user_id = auth.uid()
           AND ca.athlete_id = performance_metrics.athlete_id
         )
       );
     ```

  6. **Training loads policies:**
     ```sql

       FOR SELECT USING (

           JOIN public.coach_athletes ca ON ca.coach_id = c.id
     ```

  7. **Wellbeing assessments policies:**
     ```sql

       FOR SELECT USING (

         OR user_id = auth.uid()
       );

     CREATE POLICY "athletes_insert_own_wellbeing" ON public.wellbeing_assessments
       FOR INSERT WITH CHECK (

       );

     CREATE POLICY "coaches_select_wellbeing" ON public.wellbeing_assessments

         EXISTS (
           SELECT 1 FROM public.coaches c
           JOIN public.coach_athletes ca ON ca.coach_id = c.id
           JOIN public.athletes a ON a.id = ca.athlete_id
           WHERE c.user_id = auth.uid()
           AND (wellbeing_assessments.athlete_id = a.id OR wellbeing_assessments.user_id = a.user_id)
         )
       );
     ```

  Even though the backend uses service role key (bypasses RLS), we should add application-level filtering as defense-in-depth. This ensures that even if someone bypasses the frontend, the backend only returns data the user is authorized to see.

  **Important:** The `get_current_user` dependency from Plan 02-02 returns a Supabase user object with `user.id` (UUID string). We need to look up the athlete record for this user to get the `athlete_id` used in data tables.

  **Update `backend/app/api/endpoints/athletes.py`:**
  - The `GET /` (list athletes) endpoint:
    - For now, return only the authenticated user's own athlete profile
    - Look up athlete where `user_id = user.id`
    - Later (Phase 5, coach dashboard), this will be extended to return the coach's assigned athletes
  - The `GET /{athlete_id}` endpoint:
    - Verify the requested athlete_id belongs to the authenticated user (check `user_id = user.id`)
    - If not the owner, return 403 Forbidden
    - Later, coaches will be allowed to view assigned athletes
  - The `POST /` (create) endpoint:
    - Set `user_id` to `user.id` automatically (don't trust client input for this)
  - The `PUT /{athlete_id}` (update) endpoint:
    - Verify ownership before allowing update
  - The `DELETE /{athlete_id}` (soft delete) endpoint:
    - Verify ownership before allowing delete

  **Update `backend/app/api/endpoints/training.py`:**
  - The `GET /workouts` endpoint:
    - Look up the athlete record for the authenticated user (`user_id = user.id`)
    - If athlete_id query param is provided, verify it belongs to the authenticated user
    - If no athlete_id param, use the authenticated user's own athlete_id
  - The `GET /workouts/{workout_id}` endpoint:
    - After fetching the workout, verify it belongs to the authenticated user's athlete
  - The `POST /workouts` endpoint:
    - Set athlete_id from the authenticated user's athlete record (don't trust client input)
  - The `GET /recommendations` endpoint:
    - Filter by authenticated user's athlete_id

  **Update `backend/app/api/endpoints/performance.py`:**
  - All endpoints take `athlete_id` as a path parameter
  - For each endpoint, verify that the requested `athlete_id` belongs to the authenticated user
  - If not authorized, return 403 Forbidden

  **Helper pattern to use across all endpoints:**
  ```python
  async def get_athlete_for_user(user) -> dict:
      """Look up the athlete record for the authenticated user."""
      sb = get_supabase()
      result = sb.table("athletes").select("*").eq("user_id", user.id).single().execute()
      if not result.data:
          raise HTTPException(status_code=404, detail="No athlete profile found for this user")
      return result.data
  ```
  Add this helper to the athletes endpoint file (or to a shared location if you prefer, but keeping it in athletes.py is fine for now).
