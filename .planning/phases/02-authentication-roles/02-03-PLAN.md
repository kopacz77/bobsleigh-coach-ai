  <action>
  **Approach for role storage:** Use Supabase's `app_metadata` for role assignment. The `app_metadata` field is NOT writable by the user (only by service role or Supabase dashboard), making it the secure choice for roles. The `user_metadata` is user-writable and should not be trusted for authorization.

  However, since `app_metadata` can only be set via admin/service-role API, we need a Supabase database trigger to set the default role on new user signup, and admin endpoints to change roles later.

  **Create `backend/sql/auth_roles_migration.sql`:**
  This SQL file should be run in the Supabase SQL editor. It:

  1. Creates a trigger function that sets default `app_metadata.role = 'athlete'` on new user creation:
     ```sql
     -- Function to set default role on signup
     CREATE OR REPLACE FUNCTION public.handle_new_user()
     RETURNS trigger AS $$
     BEGIN
       -- Set default role to 'athlete' in app_metadata
       UPDATE auth.users
       SET raw_app_meta_data = raw_app_meta_data || '{"role": "athlete"}'::jsonb
       WHERE id = NEW.id;

       RETURN NEW;
     END;
     $$ LANGUAGE plpgsql SECURITY DEFINER;

     -- Trigger on auth.users insert
     DROP TRIGGER IF EXISTS on_auth_user_created ON auth.users;
     CREATE TRIGGER on_auth_user_created
       AFTER INSERT ON auth.users
       FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
     ```

  2. Creates a helper function to check user role (useful for RLS policies in Plan 02-04):
     ```sql
     -- Function to get current user's role (for use in RLS policies)
     CREATE OR REPLACE FUNCTION public.get_user_role()
     RETURNS text AS $$
       SELECT COALESCE(
         (auth.jwt() -> 'app_metadata' ->> 'role'),
         'athlete'
       );
     $$ LANGUAGE sql STABLE SECURITY DEFINER;
     ```

  3. Adds a comment explaining how to promote a user to coach:
     ```sql
     -- To promote a user to coach, run:
     -- UPDATE auth.users SET raw_app_meta_data = raw_app_meta_data || '{"role": "coach"}'::jsonb WHERE id = '<user-uuid>';
     -- Or use the Supabase dashboard: Authentication > Users > Select user > Edit > App metadata > {"role": "coach"}
     ```

  **Update `frontend/src/hooks/useAuth.ts`:**
  - Add `role` to the returned object, derived from the session:
    ```typescript

    ```
  - Export type for role: `type UserRole = 'coach' | 'athlete' | 'admin';`
  - Add `isCoach` and `isAthlete` boolean convenience properties:
    ```typescript
    isCoach: role === 'coach',
    isAthlete: role === 'athlete' || role === undefined,
    ```
  - The role is read from `app_metadata` which is included in the Supabase JWT and session object automatically. No additional API call needed.
