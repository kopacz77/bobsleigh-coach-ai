    3. **Update Pydantic schemas for UUID strings** -- The Supabase database uses UUID primary keys. All Pydantic schemas must use `str` IDs instead of `int`:

       In `backend/app/schemas/athlete.py`:
       - Change `Athlete.id` from `int` to `str`
       - Change `Athlete.user_id` from `int` to `str` (make Optional since Supabase schema has nullable user_id)
       - Add missing fields that exist in Supabase schema: `training_level`, `is_active`
       - Keep `AthleteBase`, `AthleteCreate`, `AthleteUpdate` inheritance pattern

       In `backend/app/schemas/training.py`:
       - Read the file first to understand current shape
       - Change all `id` fields from `int` to `str`
       - Change `athlete_id` from `int` to `str`
       - Ensure `workout_type` field matches Supabase column name (not `type`)
       - Add missing fields: `rpe`, `is_completed`, `training_phase`

       In `backend/app/schemas/token.py`:
       - Read first, likely minimal changes needed
       - Ensure `sub` field in TokenData can be a UUID string

    4. **Update session.py** -- Add a Supabase client factory alongside the existing SQLAlchemy session (we keep SQLAlchemy for potential future use but add supabase-py for immediate data access):
       ```python
       from supabase import create_client, Client
       from app.core.config import settings

       def get_supabase() -> Client:
           """Get a Supabase client with service role key for backend operations."""
           if not settings.SUPABASE_URL or not settings.SUPABASE_SERVICE_ROLE_KEY:
               raise RuntimeError("Supabase credentials not configured. Set SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY environment variables.")
           return create_client(settings.SUPABASE_URL, settings.SUPABASE_SERVICE_ROLE_KEY)
       ```
       Keep the existing SQLAlchemy engine/session/Base code in place -- do NOT delete it.

    5. **Fix backend Dockerfile** -- The current `backend/Dockerfile` is a Node.js Dockerfile (copies from node:20-alpine, runs `npm ci`, runs Next.js). Replace it with a proper Python Dockerfile:
       ```dockerfile
       FROM python:3.11-slim

       WORKDIR /app

       # Install system dependencies for psycopg2
       RUN apt-get update && apt-get install -y --no-install-recommends \
           gcc libpq-dev \
           && rm -rf /var/lib/apt/lists/*

       # Copy and install Python dependencies
       COPY requirements.txt .
       RUN pip install --no-cache-dir -r requirements.txt

       # Copy application code
       COPY . .

       # Expose port
       EXPOSE 8000

       # Run the application
       CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
       ```
