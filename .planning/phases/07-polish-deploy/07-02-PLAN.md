  <action>
    1. Create `backend/app/db/repositories/` directory with `__init__.py`.

    2. Create `backend/app/db/repositories/base.py`:
       - Import `text` from sqlalchemy and `engine` from `app.db.session`
       - `BaseRepository` class with these methods:
         - `_execute(query: str, params: dict = None) -> list[dict]` -- executes SELECT, returns list of dicts
         - `_execute_one(query: str, params: dict = None) -> dict | None` -- returns first row or None
         - `_execute_insert(query: str, params: dict = None) -> dict` -- executes INSERT RETURNING, commits, returns dict
         - `_execute_update(query: str, params: dict = None) -> dict | None` -- executes UPDATE RETURNING, commits
         - `_execute_delete(query: str, params: dict = None) -> bool` -- executes DELETE, commits, returns True
       - All methods use `with engine.connect() as conn:` pattern
       - Insert/update/delete must call `conn.commit()` after execute
       - Map result rows with `dict(row._mapping)` for SQLAlchemy 2.0 compatibility

    3. Create `backend/app/db/repositories/athlete_repo.py` -- `AthleteRepository(BaseRepository)`:
       - `get_by_user_id(user_id: str) -> dict | None` -- SELECT * WHERE user_id = :uid AND is_active = true
       - `get_active_by_user_id(user_id: str) -> list[dict]` -- returns list for the GET /athletes endpoint
       - `get_by_id(athlete_id: str) -> dict | None`
       - `create(data: dict) -> dict` -- INSERT ... RETURNING *
       - `update(athlete_id: str, data: dict) -> dict | None` -- dynamically build SET clause from data dict keys
       - `soft_delete(athlete_id: str) -> dict | None` -- UPDATE SET is_active=false RETURNING *

    4. Create `backend/app/db/repositories/exercise_repo.py` -- `ExerciseRepository(BaseRepository)`:
       - `search(query: str = None, category: str = None, muscle_group: str = None, equipment: str = None, offset: int = 0, limit: int = 50) -> list[dict]`
         - Build WHERE clause dynamically: `name ILIKE '%' || :q || '%'` for text search, `category = :cat`, `muscle_groups @> ARRAY[:mg]` for array contains, `equipment_needed @> ARRAY[:eq]`
       - `get_by_id(exercise_id: str) -> dict | None`
       - `get_all_active(offset: int = 0, limit: int = 50) -> list[dict]` -- WHERE is_active = true

    5. Update `backend/app/db/session.py`:
       - Keep the SQLAlchemy engine, SessionLocal, Base, and get_db as-is
       - Keep get_supabase() for now (will be removed after all files are migrated) but add a deprecation comment

    6. Migrate `backend/app/api/endpoints/athletes.py`:
       - Remove `from app.db.session import get_supabase`
       - Add `from app.db.repositories.athlete_repo import AthleteRepository`
       - Create module-level `athlete_repo = AthleteRepository()`
       - Replace each `get_supabase().table("athletes")...` call with the corresponding repository method
       - Keep the same error handling pattern (HTTPException 404, 403, 503, 500)
       - Keep `_verify_ownership` and `get_athlete_for_user` helper functions but have them use the repo

    7. Migrate `backend/app/api/endpoints/exercises.py`:
       - Remove Supabase import, add ExerciseRepository
       - Replace all PostgREST query builder calls with repository methods
       - The exercise search uses .ilike() with asterisk wildcards in Supabase -- replace with SQL ILIKE '%' || :q || '%'
       - The .contains() for array filtering becomes `@>` operator in SQL

    IMPORTANT: For the `update` method, build the SET clause dynamically from the data dict keys. Example:
    ```python
    set_clauses = ", ".join(f"{k} = :{k}" for k in data.keys())
    query = f"UPDATE athletes SET {set_clauses}, updated_at = NOW() WHERE id = :id RETURNING *"
    ```
    This avoids hardcoding column names while keeping it safe (keys come from Pydantic model_dump, not user input).
