<objective>
Add offline workout data queuing so athletes can log workouts even with poor gym connectivity. Data saves to IndexedDB via Dexie.js and syncs automatically when the network returns.

Purpose: Gyms often have poor cell/wifi signal. Athletes must not lose workout data because of connectivity issues. This plan adds a local-first data queue for the active workout flow -- if the POST to /api/training/workouts fails, the data is saved locally and retried automatically when online.

Output: Dexie.js IndexedDB store for pending workouts. useOfflineSync hook with queue-and-retry logic. Visual offline indicator. ActiveWorkout integration with offline fallback.
</objective>

  <action>
    1. Install Dexie.js: `cd frontend && pnpm add dexie`

    2. Create `frontend/src/lib/offlineDb.ts`:
       - Import `Dexie` and `Table` from 'dexie'
       - Define `PendingWorkout` interface:
         ```typescript
         interface PendingWorkout {
           id?: number;          // auto-increment local ID
           payload: {            // exact shape of POST /api/training/workouts body
             athlete_id: string;
             date: string;
             workout_type: string;
             exercises: Array<{
               exercise_id: string;
               sets: number;
               reps: number;
               weight_kg: number;
               rpe?: number;
             }>;
           };
           created_at: string;   // ISO timestamp when queued
           retries: number;      // number of sync attempts
           last_error?: string;  // last sync error message
         }
         ```
       - Create `class OfflineDb extends Dexie`:
         - `pendingWorkouts!: Table<PendingWorkout, number>`
         - Version 1 schema: `pendingWorkouts: '++id, created_at'`
       - Export singleton: `export const offlineDb = new OfflineDb()`

    3. Create `frontend/src/hooks/useOfflineSync.ts`:
       - `useOfflineSync()` hook that returns:
         - `isOnline: boolean` -- tracks navigator.onLine status
         - `pendingCount: number` -- number of items in offlineDb.pendingWorkouts
         - `queueWorkout(payload: PendingWorkout['payload']): Promise<void>` -- adds to IndexedDB
         - `syncPending(): Promise<{ synced: number; failed: number }>` -- tries to POST each pending workout, removes on success, increments retries on failure
       - On mount: listen for `online` and `offline` events on `window`
       - When `online` event fires: call `syncPending()` automatically
       - Poll pendingCount on interval (every 30 seconds) to keep UI updated
       - Use `useLiveQuery` from 'dexie-react-hooks' if available, otherwise manual polling
       - Install dexie-react-hooks: `pnpm add dexie-react-hooks` (may not exist as separate package in newer Dexie -- check. If Dexie 4.x has built-in React hooks, use those instead)
       - SSR-safe: check `typeof window !== 'undefined'` before accessing navigator or window events
       - Clean up event listeners on unmount
  </action>
  <verify>
    Run: `cd frontend && pnpm build` -- should succeed
    Run: `grep "dexie" frontend/package.json` -- should exist
    Run: `grep "useOfflineSync" frontend/src/hooks/useOfflineSync.ts` -- should exist
  </verify>

    - useOfflineSync hook queues workouts on failure, syncs on reconnect
    - Auto-sync triggers on 'online' event
    - SSR-safe (no server-side navigator/window access)
  </done>
