  <action>
    1. Create `backend/app/core/auth_provider.py` with:
       - `AuthUser` dataclass with fields: `id: str`, `email: str`, `app_metadata: dict`, `user_metadata: dict` (must match the attribute access pattern of Supabase User object since all endpoints use `user.id`, `user.email`, `user.app_metadata`)
       - `AuthProvider` Protocol with `get_user(token: str) -> Optional[AuthUser]` method
       - `DevAuthProvider` class that ignores the token and always returns a user configured from settings (DEV_USER_ID, DEV_USER_EMAIL, DEV_USER_ROLE). Role goes into `app_metadata["role"]`.
       - `SupabaseAuthProvider` class that calls `get_supabase().auth.get_user(token)` and maps the result to AuthUser. Import get_supabase lazily inside the method to avoid import errors when supabase is not configured.
       - Factory function `get_auth_provider() -> AuthProvider` that reads `settings.AUTH_PROVIDER` and returns the appropriate implementation.

    2. Update `backend/app/core/config.py`:
       - Add settings: `AUTH_PROVIDER: str = "dev"` (options: "dev", "supabase")
       - Add settings: `DEV_USER_ID: str = "00000000-0000-0000-0000-000000000001"`
       - Add settings: `DEV_USER_EMAIL: str = "coach@dev.local"`
       - Add settings: `DEV_USER_ROLE: str = "coach"`

    3. Update `backend/app/core/security.py`:
       - Import `get_auth_provider` from auth_provider module
       - Replace `get_supabase().auth.get_user(token)` with `get_auth_provider().get_user(token)`
       - Map the AuthUser result to match the same return type pattern (the AuthUser dataclass already has the same attribute names, so endpoints using `user.id`, `user.app_metadata` etc. will work unchanged)
       - Update both `get_current_user` and `get_optional_user` functions
  </action>

    Expected: prints dev user ID, email, and metadata with role
  </verify>
  <done>
    - DevAuthProvider returns configured user for any token
    - SupabaseAuthProvider wraps existing Supabase auth logic
    - security.py uses provider abstraction instead of direct Supabase calls
    - All existing endpoint code using `user.id`, `user.email`, `user.app_metadata` works unchanged
  </done>
