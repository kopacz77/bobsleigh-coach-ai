  <name>Task 1: Build injury risk assessment service</name>
  <files>backend/app/services/injury_risk_service.py</files>
  <action>
Create InjuryRiskService that combines multiple risk signals into a single score. This is a rule-based assessment (NOT the ML model from ml/models/injury_risk_model.py which requires training data).

Implement `assess_risk(athlete_id: str) -> dict` that returns:
```python
{
    "score": 0.0-1.0,
    "level": "low" | "moderate" | "high",
    "factors": ["list of contributing factors"],
    "acwr": float,  # acute:chronic workload ratio
}
```

Risk components (from 06-RESEARCH.md):

1. **TSB component (0-0.3):**
   - TSB < -30: +0.3 ("Severe fatigue TSB < -30")
   - TSB < -20: +0.2 ("High fatigue TSB < -20")
   - TSB < -10: +0.1 ("Moderate fatigue")

2. **ACWR component (0-0.3):**
   - Calculate ACWR = ATL / CTL (from PMCService)
   - ACWR > 1.5: +0.3 ("ACWR > 1.5 danger zone")
   - ACWR > 1.3: +0.15 ("ACWR rising 1.3-1.5")
   - ACWR < 0.6: +0.15 ("Under-prepared ACWR < 0.6")
   - ACWR < 0.8: +0.1 ("Under-prepared ACWR < 0.8")

3. **Wellbeing trend component (0-0.2):**
   - Query last 3 days of wellbeing_assessments for this athlete's user_id
   - Calculate average readiness using the _calculate_readiness formula from coach_service.py
   - avg_readiness < 4: +0.2 ("Poor readiness 3-day avg < 4")
   - avg_readiness < 6: +0.1 ("Below-average readiness")

4. **Sleep component (0-0.2):**
   - From same 3-day wellbeing data
   - avg_sleep_quality < 4: +0.2 ("Poor sleep quality")

Classification:
- score >= 0.6: level = "high"
- score >= 0.3: level = "moderate"
- else: level = "low"

Cap score at 1.0.

The service needs to look up athlete.user_id from athletes table to query wellbeing_assessments (which use user_id, not athlete_id).

Follow existing patterns: class-based, async, get_supabase(), PMCService for PMC data.

<task type="auto">
  <name>Task 2: Create plan API endpoints with approval workflow</name>
  <files>backend/app/api/endpoints/plans.py, backend/app/api/router.py</files>
  <action>
Create plans.py with the following endpoints, following the exact patterns from coach.py and training.py (raw dicts from Supabase, no response_model, _get_user_role helper, try/except blocks, Depends(get_current_user)):

**Coach-only endpoints (require coach role):**

1. `GET /api/plans/pending` - Get all plans with status "pending_review" for the coach's athletes
   - Get coach_id via CoachService.get_coach_id(user.id)
   - Get athlete_ids via CoachService.get_athlete_ids(coach_id)
   - Query weekly_plans table WHERE athlete_id IN athlete_ids AND status = "pending_review"
   - Join athlete name from athletes table (or include in response)
   - Order by week_start ASC, created_at ASC

2. `POST /api/plans/generate` - Generate a plan for a single athlete
   - Body: { athlete_id: str, week_start: str }
   - Validate week_start is a Monday
   - Call PlanGenerationService.generate_plan(athlete_id, week_start)
   - Also call InjuryRiskService.assess_risk(athlete_id) and attach to the plan
   - Return the created plan

3. `POST /api/plans/generate-batch` - Generate plans for all coach's athletes
   - Body: { week_start: str }
   - Use FastAPI BackgroundTasks to avoid HTTP timeout
   - Call PlanGenerationService.generate_plans_batch(coach_id, week_start) in background
   - Return immediately: { "message": "Generating plans for N athletes", "athlete_count": N }

4. `POST /api/plans/{plan_id}/approve` - Approve a pending plan
   - Verify plan exists and status == "pending_review"
   - Update: status = "approved", approved_at = now, approved_by = coach_id
   - Return updated plan

5. `POST /api/plans/{plan_id}/reject` - Reject a plan with feedback
   - Body: { rejection_notes: str } (required, non-empty)
   - Verify plan exists and status == "pending_review"
   - Update: status = "rejected", rejected_at = now, rejected_by = coach_id, rejection_notes = notes
   - Optionally trigger regeneration as background task (generate new version with parent_plan_id set)
   - Return updated plan

6. `GET /api/plans/{plan_id}` - Get a single plan by ID (coach only)
   - Return full plan with plan_data

**Athlete endpoints:**

7. `GET /api/plans/current` - Get the athlete's approved plan for the current week
   - Get athlete_id from _get_athlete_id_for_user(user) (same pattern as training.py)
   - Calculate current week's Monday date
   - Query weekly_plans WHERE athlete_id = X AND status = "approved" AND week_start = current_monday
   - If no plan, return 204 No Content (same pattern as wellbeing/checkin/today)
   - If found, return the plan

**Register the router in router.py:**
- Import plans module
- Add: `api_router.include_router(plans.router, prefix="/plans", tags=["Plans"])`

Use the same error handling patterns as coach.py: try/except HTTPException (re-raise), ValueError -> 404, RuntimeError -> 503, generic Exception -> 500.
